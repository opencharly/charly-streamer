# 2026.243.0847 — fix(audio): constrain the source caps — desktop audio was left-channel-only

## Summary

**Audio attached, flowed, and was still wrong.** Reading the actual PipeWire link graph on a live
pod rather than trusting the green check:

```
cstream-speaker:monitor_FL  |->  cstream-streamer:input_MONO
```

One port. **`monitor_FR` was linked to nothing** — the right channel was not mixed down, it was
dropped. Desktop audio would have shipped left-channel-only, and every check passed, because a link
existed and audio flowed.

A capsfilter now sits between `pipewiresrc` and the queue, carrying two constraints.

## Why it must be upstream of `audioconvert`

Downstream, conversion simply *satisfies* the request and the source still negotiates one channel.
The constraint only does anything where it can reach the negotiation — directly on the source.

**`channels=2`, for a sink monitor only.** `cstream-mic` is legitimately mono; demanding two
channels there would fail negotiation for no reason. The constraint is tied to `capture_sink`, not
applied blindly.

**`audio/x-raw`, always.** `pipewiresrc` serves audio *and* video. Against a caps-agnostic peer it
negotiates **video**, finds no video node, and reports:

```
stream error: target not found
```

which reads as *"your node is missing"* and actually means *"no **video** target"*. That message
cost an hour: I chased a missing node, a wrong runtime dir, `object.serial` vs node id, and
wireplumber defaults before isolating it. What finally settled it was `pw-record` capturing 1.5 MB
happily from the same node — proving PipeWire was fine and the fault was the GStreamer element's
negotiation.

## A mistake this PR also fixes in its own test

While writing this I built the capsfilter and **forgot to add or link it**. It compiled, it ran, it
did nothing — and every existing assertion still passed, including the one named
"builds_and_links_the_chain".

So that test now asserts the **wiring**: the filter is in the pipeline, its upstream peer is
`pipewiresrc` *specifically*, and it carries `channels=2`. Verified discriminating — removing it
from `link_many` fails the test, restoring passes:

```
# with `&caps` removed from link_many
test audio::tests::attach_really_builds_and_links_the_chain ... FAILED
# restored
test result: ok. 13 passed; 0 failed
```

### What is not claimed

That stereo now reaches the browser. This pins the *source* negotiation; confirming two channels
survive to the encoded track is `pod-cstream`'s bed, which adopts this pin next and can assert both
monitor ports are linked.

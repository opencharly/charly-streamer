# 2026.243.0757 — fix(audio): make the branch OPT-IN — an unreachable audio path must not cost the desktop

## Summary

**`#9` shipped the audio branch enabled by default. That was wrong, and the pod bed showed it
within one run.** This makes it opt-in.

The reasoning in `#9` — *silently absent audio is the failure worth preventing* — was right about
audio and wrong about **blast radius**.

## What actually happened

`attach` returns an error when the audio path is unavailable, `main` propagates it, and the process
exits. **That process is the Wayland parent.** Measured on `check-cstream-pod` against a real pod:

```
cstream-parent    FATAL    Exited too quickly
cstream-hyprland  RUNNING  uptime 0:00:06        (restart-looping, no parent display)
pipewire          RUNNING
```

```
Error: bringing the pipeline to PLAYING:
  /GstPipeline:pipeline0/GstPipeWireSrc:pipewiresrc0: Failed to connect
```

and the consumer-side frame probe then **hung for eleven minutes** waiting on media that would
never arrive. An optional feature took down the product, and it presented as a bed hang rather than
as an audio error.

## The audio path is not reachable in that pod at all yet

Independent of this change, and worth recording because it is the actual remaining WP6 work:

```
$ pw-cli ls Node          → cstream-speaker (Audio/Sink, id 30)
                            cstream-mic     (Audio/Source/Virtual, id 31)     both present

$ gst-launch-1.0 pipewiresrc target-object=cstream-mic ! fakesink
  stream error: target not found        # and identically for id 31, path=31, and NO target

$ pw-cli ls Metadata      → settings, schema-sm-settings        # no `default` object
```

So `pipewiresrc` fails to resolve **every** target including the default, and wireplumber has
established no defaults. Two separate things were also found and fixed on the way here — the
runtime dirs differ (`/tmp/xdg-runtime` for PipeWire vs `/tmp/cstream-rt` for the streamer), and
`gst-plugin-pipewire` is not supplied by `pod-pipewire` — but neither is sufficient, and none of it
belongs in this commit.

## Why opt-in does not weaken the original argument

The two failures are asymmetric, and the fix keeps both covered:

| case | before | after |
|---|---|---|
| never asked for audio, path unavailable | **loses the desktop** | no audio branch at all |
| asked for audio, path broken | loud abort | loud abort — unchanged |
| asked for audio, misconfigured → silence | caught by the assertions | caught, unchanged |
| typo after opting in (`of`) | audio stays on | audio stays on — `of` is read as a *target*, so it fails on a node that does not exist rather than quietly disabling |

Only the exact word `off` disables it. Having opted in, you cannot lose audio to a typo — that
asymmetry is the point.

Nothing enables this yet. `pod-cstream` turns it on when the path works, and its bed check on the
monitor link is what will prove it.

# 2026.241.1942 — feat(leader): the session leader's privilege drop, with irreversibility proven

## Summary

`cstream-leader` — the per-user session leader. It runs as root exactly long enough to authenticate a user and open a PAM session, then drops to that user and must **never** regain privilege.

This PR lands the privilege-drop core and its contract. The PAM binding itself follows; this is the part that must be right first, because everything above it is only as safe as the drop.

## Three properties that fail silently

Each is expressed as data or an explicit check rather than a comment, so a regression is caught rather than reasoned about:

**1 — Drop order.** `setgroups` must precede `setgid`, and `setgid` must precede `setuid`. After `setuid` the process no longer has the privilege to change groups, so a reordering leaves the session holding **root's supplementary groups** while appearing to have dropped. The order is exported as `DROP_ORDER` so a test can assert it without needing root.

**2 — Irreversibility.** `setuid` does nothing useful if the process kept a saved-set-uid — and such a process reports the *correct effective uid* while still being able to call `setuid(0)` successfully. So `verify_irreversible` **attempts to regain root** and fails the drop if it succeeds. Checking the ids alone would pass a retained-privilege session.

**3 — Session class.** `XDG_SESSION_CLASS=user` is what makes logind create a user-class session. Without it the per-user `user@UID.service` tree — which owns the desktop's units — is never started, and the desktop then fails far from this cause.

Dropping to uid 0 is **refused outright** rather than treated as a no-op, so a misconfigured deployment cannot yield a silently-root session.

## How tested

```
$ cargo fmt --all --check                              clean
$ cargo clippy --workspace --all-targets -- -D warnings clean
$ cargo test --workspace                                16 passed across 3 suites

test drop_order_surrenders_groups_before_identity ... ok
test refuses_to_drop_to_root ... ok
test session_env_sets_the_class_logind_needs ... ok
test a_failed_drop_is_an_error_not_a_silent_pass ... ok
```

The last test is the important one for an unprivileged CI runner: an unprivileged process **cannot** drop to another uid, so the call must return `Err`. A version that continued to `setuid` and reported success would be a privilege-retention bug, and that test fails it. It skips itself under root, where it would assert nothing.

## What is NOT proven here

The PAM `authenticate` / `acct_mgmt` / `open_session` sequence needs root and a real PAM stack, so it is not exercised by this diff. **The login path remains unproven**, and I am not claiming otherwise. Proving it needs the `check-cstream-vm` bed from **WP7/WP9** of the cstream plan — a systemd venue where logind is real — which is a separate change against `distro-cachyos` and cannot land before this crate is tagged.

# 2026.243.0711 — feat(WP6): the outbound audio branch — capture the speaker monitor into the WebRTC sink

## Summary

**WP6's capture half.** The desktop has had two virtual audio endpoints since `pod-cstream#14`
(`cstream-speaker`, `cstream-mic`) and nothing attached to them. This adds the branch that turns
the speaker into an outbound track:

```
pipewiresrc ! queue ! audioconvert ! audioresample ! <the same webrtcsink the video branch feeds>
```

Four files: a new `audio` module, its registration in `lib.rs`, the wiring in `main.rs`, and one
property in `webrtc.rs`.

## Three decisions worth stating

**Raw audio in, not encoded.** The video branch feeds raw video and lets `webrtcsink` choose and
insert the encoder — that is the entire reason `rank.rs` exists. Encoding in this module would
bypass the sink's own codec negotiation and put a second, unnegotiated encoder in the graph, so
audio follows the same shape.

**`audio-caps` is pinned to opus**, for the reason `video-caps` is pinned to h264. Opus is the one
audio codec every WebRTC implementation is required to support; leaving the choice open invites a
browser-specific *"connects but no sound"* that looks exactly like a capture bug.

**`stream.capture.sink = true` is the load-bearing line.** `cstream-speaker` is a **sink**, and the
outbound track is its **monitor** — what the sink receives, observed from the other side. PipeWire
routes a capture stream to a monitor only when the stream carries that property. Without it,
targeting a sink asks to record from an input and there is nothing to read: **the stream still
connects, and is simply silent.** That is worse than an error, because every liveness check keeps
passing — the same failure shape as a check that reports success having done nothing.

`CSTREAM_AUDIO=off` disables the branch and leaves the graph byte-identical to the video-only one.
Only that exact word disables it — a typo keeps audio **on**, because silently-absent audio is the
failure this module exists to prevent, and a typo must not be able to cause it.

## How tested

**The full gate, on the final committed tree (`bdf752d`, clean):**

```
$ cargo build --workspace                                   → exit 0
$ cargo test  --workspace                                   → exit 0   (41 passed, 0 failed)
$ cargo clippy --workspace --all-targets -- -D warnings     → exit 0
$ cargo fmt --all --check                                   → exit 0
```

Clippy caught one real thing on the way (`needless_update` — a `..Default::default()` that could
not fill anything), and `fmt` caught an unformatted block in the new test; both are fixed rather
than allowed.

**The changed path actually executes.** Config-struct tests alone would leave every way this can
really fail untested — a misspelled element, a property `pipewiresrc` does not have (a GObject
property set that misses is a *runtime warning*, not a compile error), or a chain that will not
link. So `attach_really_builds_and_links_the_chain` constructs the real elements, sets the real
properties, links the real chain, and then reads `stream.capture.sink` back off the **constructed
element** rather than off the config that asked for it:

```
test audio::tests::attach_really_builds_and_links_the_chain ... ok
```

`webrtcsink` is not required for that — `fakesink` stands in, and accepts any caps.

**Proven discriminating, not vacuous.** Misspelling the property makes it fail, and restoring makes
it pass:

```
# b.field("stream.capture.sink" → "stream.capture.WRONG")
test audio::tests::capture_sink_is_what_reaches_the_stream_properties ... FAILED
test audio::tests::attach_really_builds_and_links_the_chain            ... FAILED
# restored
test result: ok. 9 passed; 0 failed
```

The test also skips loudly (`SKIP: gst-plugin-pipewire absent`) rather than passing quietly where
the plugin is missing. On this host it is present, so it ran.

**A flake I introduced and then removed.** Four tests set the same env var; the environment is
per-process while `cargo test` runs tests on parallel threads. They passed on the first run, which
is exactly how that class of flake hides. Serialised behind a mutex, then confirmed over **8
consecutive runs, 0 failures**.

### What is NOT proven here, and where it will be

No audio sample has crossed a WebRTC connection. This exercises construction and linking; it does
not exercise a real `webrtcsink` requesting an audio pad, PipeWire actually routing the monitor, or
a browser decoding opus. That is WP6's bed gate — `wpctl status` showing the cstream defaults, an
audio-bitrate assertion, and `pw-record --target cstream-mic` — and it lands in `pod-cstream`, which
is where the pod bed lives and which can only pin this once it is merged and tagged. That is the
same producer→consumer split WP4 used (`charly-streamer#8` → `pod-cstream#9`), and it is why the
tier below is not `fully tested and validated`.

## Rulebook compliance

- **R1 — RCA every anomaly.** Two failures during development (a clippy lint, a parallel-test env
  race) were fixed at cause rather than suppressed; the race was confirmed gone by repetition, not
  by one green run.
- **R3 — no duplication.** No second encoder: the sink's existing negotiation is reused. The two
  endpoint names live in one place as constants, since three files address them by `node.name`.
- **R4 — no workarounds.** No sleeps, no retries; the capture-sink property is the documented
  mechanism, not a trick.
- **R6 — git safety.** Working tree checked before staging and clean after commit; `feat/` branch
  off a fresh clone; the only history rewrite is an amend of an unpushed commit; no force-push, no
  direct push to `main`, no hook bypass.
- **R7 — prove the gate, not the plan.** Every command above pasted with its exit code, from the
  final committed tree.

## Change classification

- **Change class:** Rust product code — one new module plus three small edits. No schema, no
  workflow, no candy, no pins.
- **Verification gate:** `cargo build` / `test` / `clippy -D warnings` / `fmt --check` on the final
  committed tree, plus a negative control proving the new test discriminates.
- **Breaking change + rollback:** none for existing deployments — `CSTREAM_AUDIO=off` restores the
  previous graph exactly, and rollback is a revert.
- **Producer → consumer order:** this repo merges and tags → `pod-cstream` pins it and adds the WP6
  bed gate.

**Attribution tier:** analysed on a live system — the changed path ran live against real GStreamer
elements with retained output, but WP6's bed gate has not run, and no audio has yet streamed.

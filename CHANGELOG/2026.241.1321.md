# 2026.241.1321 — ci: gate the streamer as Rust product code, not as a candy

## Summary

This repo is **product code, not a candy** — it ships no `charly.yml`. Its `.github` was scaffolded from a layer repo, so it inherited the `candy` workflow, whose only job is:

```
.ci/charly/bin/charly box validate
```

That gate can never pass here, because there is no manifest to validate and never will be. It is removed rather than left red, and replaced with a gate that matches what this repo actually contains.

The new `rust` workflow runs the four checks the plan names for the streamer:

```
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo build --workspace
cargo test --workspace
```

It installs `libgstreamer1.0-dev` + `libgstreamer-plugins-base1.0-dev` first, because `gstreamer-rs` binds against the system GStreamer and would otherwise fail in `pkg-config` rather than in our code.

## How tested

All four gates run clean locally against this tree:

```
$ cargo fmt --all --check
(no output)

$ cargo clippy --workspace --all-targets -- -D warnings
Finished `dev` profile [unoptimized + debuginfo] target(s)
clippy rc=0

$ cargo build --workspace
Finished `dev` profile

$ cargo test --workspace
test result: ok. 8 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

The eight tests are the contract tests for the three silent-failure paths (encoder ranking, render-node rejection, input field types). The ranking test verified a load-bearing claim live on this host: `vah264enc` does start **below** webrtcsink's `MARGINAL` floor, which is precisely why promotion has to happen before the first webrtcsink is created.

`cargo test` on the CI runner will skip that one test, since a GitHub runner has no VA-API encoder — the test detects that and returns rather than failing.

# 2026.242.0605 — feat(streamer): the delivery half, with the encoder named out loud

## Summary

The streamer gets its delivery half. Until now `crates/cstream-streamer` could build the *capture*
chain (`waylanddisplaysrc → DMABuf caps → vapostproc`) and its binary did nothing but print
encoder ranks — there was no sink, no graph and no run loop, so nothing downstream could depend on
it.

**The failure this is shaped around is a stream that works while running on the CPU.** webrtcsink
enumerates encoders exactly once into a `LazyLock` and picks silently, so a host whose VA-API
encoder is present but unranked streams perfectly well at a fraction of the density and *nothing
says so*. Three pieces:

- **`webrtc::select_encoder`** — the policy table. `auto` falls through to software, `va`
  **refuses** to rather than degrading, `software` is honoured even where hardware exists (an
  operator measuring the CPU path must not be silently upgraded either). The host lookup is
  injected as a closure, so the whole table is unit-tested on a runner with no VA-API at all —
  which is every CI runner, and exactly the host where getting this wrong is invisible.
- **`webrtc::make_sink`** — `webrtcsink` with `video-caps` pinned to H.264 (left open it
  negotiates whatever the consumer prefers, routing around the encoder this host was ranked for)
  and an `encoder-setup` handler that returns **`true`**. The signal's contract is *"true if the
  encoder is entirely configured"*; returning `false` lets the default handler run afterwards and
  overwrite the tuning, so a `false` handler looks like it worked and has no effect.
- **`webrtc::verify_openable`** — because registration is not capability. A VA element is
  registered wherever the plugin loads, *including on a host whose render node it cannot open*, so
  `select_encoder` returning `Hardware` only means "the element exists". Bringing it to `READY` is
  the cheapest thing that tells those apart. It always returns the element to `NULL` afterwards,
  so one probe does not leave the render node held open for the next.

`main` assembles the real graph, brings it to PLAYING and runs a bus loop. `--probe` does exactly
that and exits, so a bed can execute the shipped graph-construction path without a browser.

- **the in-process signalling server** — added after the first review, because the serving path
  turned out not to work without it. webrtcsink's default signaller **dials**
  `ws://127.0.0.1:8443`, and with nothing listening it posts a stream error onto the bus moments
  after the pipeline reaches PLAYING. The streamer therefore built its graph, opened the hardware
  encoder, printed **both** success markers, and then died. A failure that arrives after every
  "it works" signal is the worst kind, and it is exactly why `--probe` passed while serving was
  broken. `run-signalling-server` defaults to `false`, so it has to be set explicitly.

**What this deliberately does NOT claim.** That a browser receives decodable video. That needs a
consumer to negotiate and is the gateway's half (WP6). What IS proven below is that the sink
registers as a **producer** with the signalling server and the bus loop keeps serving; frames
actually moving through the compositor is a separate gate that already exists in
`check-cstream-pod` and is green in the same run.

## Change classification

**Change class:** product code (Rust), three commits — one new module (`webrtc.rs`, 5 unit tests),
`main.rs` rewritten from a rank-printer into the real graph, one line in `lib.rs`, plus
`verify_openable` and the signalling-server properties. No new dependency, no schema, no Go, no
workflow.

**Verification gate:** the repo's Rust gate (`fmt` / `clippy -D warnings` / `test --workspace`)
plus live execution of the changed path in a `disposable: true` charly bed.

**Breaking change + rollback:** the `cstream-streamer` binary changes behaviour — it used to print
ranks and exit, it now builds a pipeline and serves. Nothing consumes it yet (`pod-cstream` gains
the build step in a sibling PR), so there is no consumer to break. Rollback is a plain revert.

Three assertions, none sufficient alone:

- **PLAYING** — the graph negotiated.
- **`registered as [Producer]`** — the in-process signalling server came up **and** the sink

- **rc 124** — the timeout killed it, so it was still blocked in the bus loop. `0` (EOS) and `1`

added for rather than merely passing.

## Rulebook compliance

- **R1 — RCA every anomaly.** Two corrections, both from testing rather than reading. First, the
  serving path *failed* when finally exercised — webrtcsink errored the pipeline right after
  PLAYING because nothing was listening on the signaller's port; root-caused to
  `run-signalling-server` defaulting to `false` rather than worked around by loosening the check.
  Second, the check was first titled *"reaches PLAYING on the hardware encoder"*, which over-claimed — `select_encoder`
  returning `Hardware` proves only that the element is **registered**. `verify_openable` and the
  second marker close that gap, and the check's description now states what it does not claim.
- **R2 — nothing parked.** The one unimplemented piece (signalling, so `encoder-setup` can fire)
  is named as WP3b rather than left implicit, and the check says so in-line.
- **R3 — no duplication.** The probe runs the shipped binary; it is not a `gst-launch` imitation
  of the graph beside it.
- **R4 — no workaround.** `STATE_TIMEOUT` is a bound on an asynchronous state change, not a sleep:
  it ends the moment the state settles, and exists so a pipeline that never negotiates fails the
  probe instead of hanging it. Every `tune_encoder` property is guarded, because the VA and
  software encoders do not share a property set and an unguarded set leaves the encoder half-tuned
  and quiet.
- **R5 — delete legacy completely.** The old `main.rs` rank-printer is gone, not left behind a
  flag.
- **R6 — git safety.** `git status` before each commit; `feat/` branch; no force-push; no direct
  push to `main`.
- **R7/R10 — prove the gate on the final committed tree.** Both blocks above ran against
  `16faf34`, and the bed is `disposable: true`.
